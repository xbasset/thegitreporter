Watching Codex Can Change When Its Tools Start

New request observers expose outcomes and available token usage. Where you put them in the sequence changes when a tool can leave the queue.

By The Git Reporter · Published October 19, 2026. Reporting as of October 19, 2026.

On October 18, openai/codex merged two hooks around model sampling attempts. A team can record what happened without putting the observer’s output into the model’s conversation. There is a timing choice. Try it.

01 / The handoffMerged code · Release unverified

A response produces a tool call. With a synchronous post observer, dispatch waits for the response and observer to finish. In background mode, dispatch can start while the response is still streaming.

  1. 1Response starts
  2. 2Tool call arrives
  3. 3Response ends
  4. 4Observer works
  5. 5Observer finishes

Our example has one configured post-request observer. It has nothing to record until this sampling attempt ends.

The choice

A record before dispatch.
Or observation alongside work.

A synchronous PostModelRequest observer holds tool dispatch until it finishes. A background observer preserves streaming dispatch. If any post handler is synchronous, that waiting rule wins.

The retry test fails one stream, then succeeds. The new hooks surround both sampling attempts.

“Completed” describes the model response. A deferred tool may not have started yet.

03 / The boundary

It can watch.
Its reply cannot steer.

“Block this request.”→Diagnostic text

These observers treat returned control directives as diagnostics. Their output cannot veto the request or add model context. Their command programs can still perform ordinary side effects; existing tool permissions still apply.

What this window shows

Status, model, turn and optional agent identity, plus errors and token usage when available. The event payload contains neither the prompt body nor the model’s internal reasoning, and has no dedicated attempt ID. This is not a census of every network retry.

Context, limits, and what to watch next

Codex already had Rust extension hooks for requests and response streams in September. The October change adds a deliberately narrower observation interface to the configurable hooks framework. User hooks are excluded from internal memory consolidation.

We inspected the merged implementation and test definitions. We did not execute the Rust suite or measure latency. Availability in a released client was not established. The next useful receipt is a containing release and a real workload comparing observer overhead and tool ordering.

Primary Evidence

  • October 18 merge: configurable request observers: https://github.com/openai/codex/pull/55144
    • Shows: Adds PreModelRequest and PostModelRequest to the hooks framework. The article describes merged implementation, not verified availability in a released client.
  • Observer mode and request lifecycle: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/core/src/session/turn.rs#L2677-L2744
    • Shows: Selects post-hook execution mode, defers tool dispatch for synchronous observers, and starts post observation after a request outcome is available.
  • Dispatch and its ordering test: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/core/tests/suite/hooks.rs#L6129-L6250
    • Shows: A parameterized test holds the response stream and post hook separately. Sync mode waits for the post hook; async and no-post modes dispatch before the response stream ends. Interrupt during the sync wait preserves usage and an aborted deferred call. Test definitions were inspected, not executed.
  • Immediate and deferred dispatch implementation: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/core/src/stream_events_utils.rs#L347-L373
    • Shows: The dispatcher normally starts a call immediately. With synchronous post observation it is deferred in a future and checked for cancellation before dispatch.
  • Event payload and diagnostic-only output: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/hooks/src/events/model_request.rs#L19-L168
    • Shows: Payload includes model, session and turn context, optional agent identity, outcome, errors and optional usage. Returned hook output is diagnostic, with no veto or context injection. No prompt body, response body or dedicated attempt ID is supplied.
  • Failure and retry observation: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/core/tests/suite/hooks.rs#L6022-L6085
    • Shows: The fixture fails one sampled response and succeeds on retry, with two pre and two post events. Failed usage is unavailable; completed usage is supplied. The observer emits control-looking JSON which is ignored as control input.
  • Mixed handlers select synchronous ordering: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/hooks/src/registry.rs#L314-L322
    • Shows: Any synchronous handler makes the post event synchronous for dispatch ordering. The interactive assumes one configured observer.
  • Earlier request/response extension hooks: https://github.com/openai/codex/pull/47679
    • Shows: September 23 work already exposed Rust extension contributors and response interceptors. October adds a narrower configurable hook interface; it is not the first instrumentation mechanism.
  • Memory-consolidation hook filtering: https://github.com/openai/codex/blob/70b3bb6d8814ab3f2045238b4ae14c43da99783b/codex-rs/hooks/src/engine/mod.rs#L148-L164
    • Shows: Internal memory consolidation excludes user-origin hook layers while retaining eligible policy/executor hooks. These user observers do not enumerate all internal model traffic.
  • Official hooks documentation: https://learn.chatgpt.com/docs/hooks
    • Shows: Describes logging and analytics use, and synchronous versus asynchronous hook execution. At inspection the event table did not include the new pair; this is context, not proof of shipping availability.

Evidence Limits

  • Source and test definitions were inspected; the Rust tests and live Codex workload were not executed. The interaction illustrates causal order and uses no measured duration, speed, cost or reliability result.
  • The change was merged on October 18. Availability in a containing client release was not established. The inspected latest stable release predates the merge.
  • Sampling attempts are not every HTTP retry or all internal model traffic. The payload has no dedicated attempt identifier or model-internal reasoning.
  • Completed is a model-response outcome, not successful tool execution or task completion. Existing tool controls remain independent of the observer.
  • Observation-only describes returned control semantics. Arbitrary hook commands may still perform side effects and take time.

How Codex made the assignment the center of the app

Every’s origin story celebrates a desktop built around agents. The public record reveals the quieter achievement underneath: separating the machinery that does the work from the interface that helps people direct it.

By The Git Reporter · Published October 16, 2026. Reporting as of October 16, 2026.

A coding agent can get a better model, a new window and a longer leash without making a person’s work easier to finish. Someone still has to supply the right files, redirect a mistaken approach and pick up the result. Codex’s history is useful because it exposes those different problems—and the danger of compressing them into one product breakthrough.

In How Codex Happened, Dan Shipper reports how OpenAI moved from a cloud product that struggled to find sustained use toward local tools and a desktop app. His interviews describe a deliberate choice to leave out a built-in code editor, putting conversations with agents at the center. That is a consequential design decision. The public code suggests a broader lesson: an assignment becomes easier to delegate when the agent can keep working while the way a person directs it changes.

An architectural option before the pivot

On April 24, 2025, OpenAI merged the first public Rust implementation of Codex CLI. The reasons were practical: a standalone executable would avoid requiring Node.js, use fewer resources and reach operating-system sandbox features directly. Its README warned that the new implementation was materially behind the existing TypeScript version.

Inside that unfinished implementation, the core library already separated agent logic from user interfaces. A protocol document described the engine accepting instructions, requesting model responses, running commands and applying patches. The interface could be a terminal or a graphical application. Interruptions and approval requests had explicit places in that design.

This was before the May cloud launch. It does not disprove the later strategic pivot described by Every, which acknowledges the April CLI as a separate early effort. It establishes something narrower: the architectural option existed before it became the center of the retrospective. Experimental code is neither a finished shared product nor a record of which internal team received the most resources.

The cloud exposed the cost of delegation

The May 16 launch gave Codex cloud tasks their own environments, where the agent could edit a repository, run tests and prepare changes for review. It also acknowledged a missing capability: users could not redirect the agent while it worked. Matching the remote environment to the developer’s actual setup remained part of the job.

The same announcement introduced a coding-optimized CLI model, codex-mini-latest. That matters when comparing the products: the cloud’s codex-1 was different, but local users did not have to wait until GPT-5 for any coding specialization. OpenAI also explicitly anticipated bringing interactive collaboration and delegated tasks together.

Claude Code offered a credible alternative route. Its February 24, 2025 preview already connected an agent to local code, tests and Git operations from the terminal. The useful advantage was concrete: work could happen in an environment the developer already used. A desktop window was not a prerequisite for delegating an engineering task.

Nor did OpenAI simply abandon the cloud. By September 15, it was describing context carried between local and remote work, conversation compaction for longer sessions, and faster cloud follow-ups through container caching. Its model pitch combined quick collaboration with sustained independent execution. The product was connecting modes of work that the origin-story shorthand can make sound like competing destinations.

What the desktop actually added

The February 2, 2026 app launch made the assignment a visible unit: project threads, parallel agents, separate working copies of a repository, and comments attached to proposed changes. Existing CLI and editor-extension history could carry into the app. Those choices reduced the work of keeping several jobs straight.

Leaving out an embedded editor did not eliminate manual editing. The launch explicitly let users open changes in their editor. The new default was to direct and review an assignment inside the app, with other tools still available. For a person managing several tasks, that can be more useful than keeping every action inside one window.

Model improvements were arriving alongside it. OpenAI’s February 5 GPT-5.3-Codex announcement combined stronger coding with broader professional knowledge and emphasized steering during execution. This is the strongest alternative to an interface-led success story: model capability, access to tools and product design improved together. The public sequence cannot tell us how much adoption each change caused.

The assignment still has a life underneath the window

A fresh October 15 change shows how concrete that underlying work remains. The merged code lets Codex suspend an unfinished parent task even when child agents exist, initiating their shutdown so the parent can later be recovered under its original turn identity. The accompanying tests check that recovery and distinguish failures while closing a child’s saved history.

It is a bounded capability. Child agents are not automatically restarted; their cleanup finishes separately; pending input may be discarded. We inspected the implementation and test definitions, without running the suite or establishing a desktop rollout. The patch illustrates a requirement of continuing work, not proof that every interruption is seamless.

For anyone choosing an agent tool, this history suggests a better practical trial than comparing chat windows. Give it a real assignment, correct it midway, leave it, and return to review what happened. Can the task retain the files, context and visible result needed to finish? That is the part of “agent-native” work a new interface has to earn.

Primary Evidence

  • Codex’s initial Rust import, merged April 24, 2025: https://github.com/openai/codex/pull/629
    • Shows: the stated distribution, runtime and sandbox reasons for an experimental Rust implementation, with an explicit warning that it remained behind TypeScript functionality.
  • Core library README at the April 24 merge: https://github.com/openai/codex/blob/31d0d7a305305ad557035a2edcab60b6be5018d8/codex-rs/core/README.md
    • Shows: the early separation of agent business logic from Rust user interfaces and a protocol for non-Rust interfaces.
  • Protocol design in that same import: https://github.com/openai/codex/blob/31d0d7a305305ad557035a2edcab60b6be5018d8/codex-rs/docs/protocol_v1.md
    • Shows: the documented relationships among model, engine, session, tasks and interfaces, including interruption and approval messages. The document warns implementation may differ from the specification.
  • OpenAI’s May 16, 2025 Codex launch: https://openai.com/index/introducing-codex/
    • Shows: isolated cloud work, unavailable mid-task course correction at launch, the distinct codex-mini-latest CLI model, and the intention to join interactive and delegated work.
  • Anthropic’s February 24, 2025 Claude Code preview: https://www.anthropic.com/news/claude-3-7-sonnet
    • Shows: a competing terminal agent already offering repository inspection, file edits, tests and Git operations before Codex’s public launch.
  • OpenAI’s September 15, 2025 Codex upgrades: https://openai.com/index/introducing-upgrades-to-codex/
    • Shows: model and product improvements spanning interactive work, independent execution, local/cloud context continuity, compaction and cloud container caching.
  • OpenAI’s February 2, 2026 desktop app launch: https://openai.com/index/introducing-the-codex-app/
    • Shows: project threads, parallel assignments, isolated worktrees, diff comments, shared CLI/IDE history and opening changes in an external editor.
  • OpenAI’s February 5, 2026 GPT-5.3-Codex launch: https://openai.com/index/introducing-gpt-5-3-codex/
    • Shows: contemporaneous model improvements, broader professional work and live steering claims. These announcements do not isolate the effects of individual changes.
  • Root suspension with live child agents, October 15, 2026: https://github.com/openai/codex/pull/54414
    • Shows: an implementation change allowing unfinished root suspension while initiating descendant shutdown, with explicit recovery and cleanup limits.
  • Implementation and test changes for root suspension: https://github.com/openai/codex/commit/341de32c33fb00b88b5dd50be70610dc59dad045
    • Shows: changes to codex_thread.rs, session/turn_suspension.rs and tests/suite/abort_tasks.rs; test cases preserve the root turn identity and separately report child writer failure without automatically restarting children.

Published Reporting

  • Dan Shipper’s published How Codex Happened: https://every.to/p/how-codex-happened
    • Shows: Every’s interviews and interpretation of the cloud/local/desktop product history, including the separate early CLI and the decision to omit an embedded editor. The published article, not private interview transcripts, supplies the attributed account used here.

Evidence Limits

  • The April Rust implementation was experimental and explicitly behind TypeScript. Its early architecture does not date its later strategic elevation or establish a finished shared production engine.
  • Public CLI code does not prove closed model training choices, private team allocation, the entire desktop implementation or why users adopted a product.
  • The October change is merged source. We did not establish its inclusion in a released desktop product or observe a production handoff.
  • Root suspension success excludes descendant cleanup; child agents are not automatically recovered, and queued input or pending requests can be discarded. Host software must complete cleanup before ownership transfers.
  • Upstream test definitions were inspected but not executed. No authenticated model session or controlled productivity comparison was performed.
  • Product announcements establish dated public promises and descriptions. Model, interface and environment changes arrived together, so the causal contribution of each remains unresolved.

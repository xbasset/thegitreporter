The harness is not the model

System Map

Eight inspection boundaries
Model boundary

Local checkpoints, adapters, quantization, inference backends, and three provider-shaped APIs form a replaceable model layer beneath the agent client.

Context and memory

Each harness keeps its own history and compaction behavior while Unsloth's launcher supplies the actual model context limits and isolated session configuration.

Tools and execution

Coding-harness launches default to client-side tools; Studio and API server tools can execute web, Python, or terminal work as the host user when enabled.

Permissions and isolation

The launcher maps permissive mode into each harness's own policy, isolates configuration where possible, and requires separate protection for API keys, tunnels, and server-side tools.

Sessions and recovery

Harness-owned session state remains distinct from Unsloth's model lifecycle; compatibility translations and bounded response healing repair selected protocol failures without becoming a universal recovery layer.

Delegation

Claude Code, Codex, OpenCode, and Pi can register the local model as a bounded subagent while retaining a different parent model and harness.

Human control

Desktop exposes model selection, training, export, serving, and model-control operations while harnesses retain approvals and execution policy.

Evidence surface

Tagged source, adapter code, route translations, tool-call healing tests, security warnings, and reproducible harness-by-model runs provide the strongest receipts.

Agent Pulse / Daily decision brief / 2026-09-03

Audit pre-trust startup paths for workspace-owned helpers

Codex's public main-branch change treats automatic startup and diagnostics as work that must stay safe before a repository is trusted. Source-build and fork operators can test that boundary without touching a production workspace: put harmless marker helpers early in a disposable workspace PATH, then exercise startup, `codex doctor --json`, and any automatic curated-plugin sync. The marker should never run; an unavailable trusted helper should produce the conservative fallback rather than a workspace-selected executable.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit pre-trust startup paths for workspace-owned helpers

What changed. The change resolves helpers used before trust from trusted system installation directories, stops `doctor` from running PATH-selected programs merely to inspect them, and gives curated-plugin Git subprocesses a sanitized environment. Its black-box test creates workspace `node_modules/.bin` marker helpers for commands including git, curl, rg, tmux, and npm, then checks startup, doctor, feedback-log collection, and plugin sync without allowing a marker to execute.

Why it matters. A workspace is not meaningfully untrusted if a convenience check can execute a program that the workspace selected first. This is a practical audit of a boundary that can otherwise hide in startup and support tooling rather than in an obvious tool call.

Claim coverage / complete 29 / 29

Codex source-build or fork operators, and builders of comparable workspace-aware coding agents 20–30 minutes in a disposable environment

Run a disposable pre-trust helper audit

Create a disposable untrusted repository with harmless marker helpers early in its workspace-controlled PATH. Exercise startup, `codex doctor --json`, and any automatic curated-plugin synchronization. Confirm the markers do not run and a missing trusted helper takes a conservative fallback. Do not use production credentials, a real plugin checkout, or a live workspace.

Limit

These receipts establish intended main-branch source behavior and tests. They do not prove that a tagged or deployed release contains the change, that every downstream wrapper or helper is protected, or that a particular workspace had an exploitable helper.

What would change this

Revise or withdraw this call if public source or a regression shows a workspace-PATH helper executes before trust, or that automatic curated-plugin Git inherits such a helper path.

Watch next. Watch for a tagged release carrying the change and for cross-platform regression coverage that demonstrates the trusted resolver and conservative fallbacks on the packaged distributions operators actually run.

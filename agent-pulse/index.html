Pi now has a source-defined execution environment that can run agent tools on another machine while the Durable worker and its storage remain on the controller.

Today's Action

Watch / Project-specific claim
watch

Watch Pi's new remote execution package at the SSH boundary

What changed. The October 5 pi-env addition implements Durable's ExecutionEnv through a remote daemon. Its SSH bootstrap selects and deploys the matching binary; the client maps filesystem and command results back to the local interface.

Why it matters. Builders can investigate separating the machine holding agent state and model access from the machine doing file and command work, without inventing every remote tool interface themselves.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builders embedding Pi Durable with remote workspaces One package and integration-trace review

Watch a reproducible remote task

Follow a pinned package demonstration that reads, edits and runs a disposable task over SSH, then interrupts the connection. Check where state remains and how unknown mutation outcomes are reported before adopting the interface.

Reversible

Evidence Chain

3 direct receipts
Receipt 1 / earendil-works/pi / commit / Oct 5, 02:00 AM GMT+2 Remote execution environment and daemon

Introduces the remote ExecutionEnv, Rust daemon and conformance/differential test definitions.

 Receipt 2 / earendil-works/pi / docs / October 5, 2026 Pi-env package contract at v1.0.4

Describes worker/tool separation, SSH bootstrap and packaged platform binaries; this is a pinned source contract.

 Receipt 3 / earendil-works/pi / docs / October 5, 2026 Connection behavior at v1.0.4

The connection restarts after loss, while in-flight requests fail and mutation outcomes can be unknown.

Confidence / developing

Implementation, SSH settings and upstream test definitions were inspected at the containing tag; no independent SSH integration was executed.

Limit

This is an SDK capability, not evidence that the ordinary Pi terminal agent automatically runs remotely. Package installation, remote task execution and platform equivalence were not independently tested. SSH is not a sandbox, and reconnection does not resolve unknown in-flight mutations.

What would change this

A pinned package lacking the documented daemon, or a reproducible task showing incompatible tool semantics across the SSH boundary, would narrow the capability claim.

Watch next. A released-package task trace with disconnect handling and an explicit account of controller state, remote authority and completed mutations.

Pi has a model router; the useful result is the task it finishes

Pi's new virtual-model example uses Jev to choose a planning model, then changes models after the first successful file edit. It makes a routing policy inspectable without establishing that the policy saves money at the same task quality.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Watch / Project-specific claim
watch

Pi has a model router; the useful result is the task it finishes

What changed. The example thresholds a two-category complexity answer at 0.5, preserves the planning choice in session state, and moves to its implementation model after an edit or write succeeds. Scripted tests exercise the handoff, not classifier accuracy.

Why it matters. A lower-priced next call can still produce a more expensive completed task if classification, cache misses or an unsuitable handoff add work.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Teams considering Pi's experimental Jev router One evaluation plan before a routing-policy trial

Look for a matched completed-task comparison

Before adopting the example as a cost policy, require a comparison against a fixed model on the same tasks and acceptance criteria, including classifier calls, failed tasks, cache misses and all later attempts. Keep the fixed-model configuration as the baseline.

 Receipt 2 / earendil-works/pi / docs / September 28, 2026 Jev router source and operating assumptions

Confidence / developing

The merged example and scripted regression definitions agree on the routing mechanism; completed-task economics remain unmeasured in this inspection.

Limit

We inspected source and test definitions, without running the router or mapping it to an installed release. A binary probability threshold does not prove a need for a full distribution or calibrated confidence.

What would change this

A matched completed-task evaluation showing that classifier overhead and misrouting erase the proposed savings would overturn the economic rationale for this policy; a policy or release change would require a new source check.

Watch next. A public fixed-model versus routed-task evaluation with explicit acceptance criteria, full accounting and failure outcomes.

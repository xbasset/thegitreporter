Check registration before retrying a Pi MCP sign-in

Pi has added a configurable OAuth client name for MCP servers. The name is sent when registering a client; changing it does not rewrite an existing registration.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Test / Project-specific claim
action

Check registration before retrying a Pi MCP sign-in

What changed. The September 30 source change passes oauth.clientName into dynamic registration metadata and otherwise keeps Pi as the default. Its documentation says a new name requires signing out and registering again.

Why it matters. A rejected registration and a failed tool call are different failures. Checking the registered client identity can explain why a connection never reaches tool discovery.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Pi users testing an MCP server that rejects registration One isolated sign-in test

Inspect a disposable registration

In an isolated configuration using a pinned revision that includes this change, inspect the registration request against a test server you control. Use its documented client name and compare the stored registration with a fresh one. Keep the working account and configuration intact.

Evidence Chain

Receipt 1 / earendil-works/pi / commit / Sep 30, 02:00 AM GMT+2 Allow a custom OAuth client name for MCP servers

 Receipt 2 / earendil-works/pi / docs / September 30, 2026 Registration-time behavior in the changed documentation

Explains that the name is sent only during registration and changing it requires registering again.

Confidence / developing

The merged OAuth implementation and its versioned documentation agree on when the client name is sent.

Limit

We inspected source, not a live OAuth integration or an installed release. A configurable client name does not establish provider approval, authorization or successful access.

What would change this

A pinned reproduction showing the configured name absent from a fresh registration request would contradict this implementation reading.

Watch next. A public integration receipt identifying the Pi version, accepted registration and successful tool discovery.

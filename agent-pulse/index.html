Preview which Cowork instructions can travel to OpenWork

What changed. The CLI reads local marketplace and skill manifests. The inspected backend permits reading Claude-style skill instructions before optional connector setup. Personal-skill upload reads SKILL.md text, not its directory; existing plugin access is preserved on repeat import.

Why it matters. People considering another assistant can inspect what is portable before rebuilding their setup or moving a real recurring task.

Confidence / developing

Pinned source, public CLI byte comparison and synthetic discovery agree. Authenticated import and downstream tasks were not independently executed.

Limit

The live CLI does not verify deployed backend behavior. Skill instruction text can move without supporting files; connector-dependent tasks still need authorization. Repeat import is not two-way synchronization.

What would change this

A real import that fails to preserve a supported text-only skill or withholds its instructions solely for an optional disconnected connector would narrow this reading.

Today's Action

Audit / Project-specific claim
action

Find your Task-dependent plugins before upgrading OpenClaw

What changed. The SDK retirement removes Task APIs; Doctor imports eligible native recovery facts into existing session bindings only when requester ownership is established. Physical tables remain, so their presence cannot establish API compatibility.

Why it matters. An operator can preserve stored records and still lose a plugin interface or encounter work whose completion cannot be safely reassigned.

Claim coverage / complete 29 / 29

OpenClaw operators evaluating a revision containing the Tasks removal One plugin inventory and a disposable upgrade rehearsal

Inventory Task integrations and rehearse unfinished work

List plugins using runtime.tasks or the retired Task harness module. In a disposable copy with a matching backup, rehearse an upgrade with unfinished native work and inspect Doctor ownership warnings, result delivery and rollback before changing the live installation.

Confidence / developing

Landed code, migration definitions, regression cases and public SDK documentation agree on the interface removal and ownership boundary.

Limit

We did not run an upgrade or verify installed release versions. The landing record leaves some native completion and 9.4 rollback witnesses unproven, and its earlier CI pass is not a fresh full pass on the final head.

What would change this

Revise the audit if the targeted release restores compatibility or if a complete upgrade and rollback replay contradicts the documented migration boundary.

Watch next. A completed published-package native completion and rollback replay, plus the first release contract that contains the removal.

Agent Pulse / Daily decision brief / 2026-08-14

Test whether compaction can still call a tool it has forgotten

Pydantic AI now treats deferred-tool availability as evidence in the surviving conversation, not as a permanent memory of a prior discovery. Builders who compact, replay, or resume Pydantic AI agent histories should test one deferred-tool path: after the reveal or capability load falls behind a compaction boundary, a direct call should be refused until the agent searches or loads again.

One decision-worthy insight. Action, effort, and rollback. 27 / 27 included projects monitored. Methodology ›

Today's Action

Test / Project-specific claim
action

Test whether compaction can still call a tool it has forgotten

What changed. The reported change filters revealed names whose deferred capability is not represented as loaded in the current history, withholds those tools from the model's callable set, and returns a retry that identifies the recovery step. A capability loaded during one response becomes usable on the next request, when its instructions and tools can actually reach the model.

Why it matters. Context compaction and deferred tools both save prompt space, but they can otherwise leave a runtime willing to execute a name the current model context no longer explains. A bounded replay test can expose that mismatch before a resumed agent acts on an old tool assumption.

Claim coverage / complete 27 / 27

All 27 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builder or operator of a Pydantic AI agent that uses deferred tools or capabilities and can compact, replay, or resume history 20–40 minutes

Exercise one compacted deferred-tool path

In a disposable run with a harmless test tool, reveal or load one deferred capability, compact or replay the history, then request the old tool name. Verify that the call is refused without execution, that the recovery message directs the agent to search or load again, and that a later request after that recovery can call the tool. Do not use production credentials or destructive tools.

Confidence / developing

A fresh public implementation change, its accompanying documentation, and the focused availability tests agree on a narrow Pydantic AI runtime contract. The recommendation is a reversible test of that contract, not a claim about deployment or every agent framework.

Limit

These main-branch source receipts do not establish a released package, production behavior, history integrity, or compatibility across providers and other agent runtimes. The availability rule is not a substitute for an authorization system or trusted server-side history.

What would change this

Revise this call if public integration tests show a compacted or replayed Pydantic AI history can execute an unavailable deferred tool without a fresh reveal or capability load, or if an officially documented runtime path intentionally keeps such a tool callable after its evidence is removed.

Watch next. Watch for release notes and integration tests covering compacted, replayed, provider-switched, and client-submitted histories, especially whether the retry guidance remains actionable without creating a loop.

Test the restore path, not just the fork policy

Qwen Code’s fresh fork allowlist supports one bounded, project-scoped test: if a parent uses `fork_tools` to narrow a background child, stop and verify the restriction after the child is revived, not only at launch. The public implementation keeps an empty list as deny-all, rejects a forbidden call before construction or approval, stores the policy in fork metadata, and reapplies it to the current parent-derived registry when the fork resumes.

One decision-worthy insight. Action, effort, and rollback. 24 / 24 included projects monitored. Methodology ›

Today's Action

Test / Project-specific claim
action

Test the restore path, not just the fork policy

What changed. The new optional `fork_tools` parameter leaves model-visible declarations intact while applying a separate execution gate. Exact tool names and bounded MCP patterns can be allowed; unknown names fail closed by matching nothing; and a denied call receives a synthetic response before it can construct a tool, trigger a hook, classify permissions, schedule, or ask for approval. On cold revival, the current system instruction and tool registry are rebound while the launch-time allowlist is restored from the persisted sidecar.

Why it matters. A policy that exists only in the launch request is not a reliable delegated-work boundary. An agent can resume after a parent changes tools, reconnects MCP servers, or replaces context. Testing the restored gate turns an attractive configuration feature into an observable recovery invariant.

Claim coverage / complete 24 / 24

Qwen Code operator or integrator using background fork subagents 20–30 minutes

Run one deny-all-and-resume drill

In an isolated test workspace, launch a fork with `fork_tools: []`, attempt one harmless built-in tool call, then stop and revive the fork. Verify before and after revival that the call is rejected before an approval prompt or tool hook is reached. Repeat with one explicitly allowed read-only tool, and record which parent runtime supplied the policy. Do not treat a passing result as a filesystem or administrator sandbox guarantee.

Limit

This is source-level Qwen Code evidence. It does not establish a released build, behavior across every CLI, desktop, daemon, or IDE surface, or an administrator-enforced sandbox. The design explicitly says the parent model or caller supplies the policy.

What would change this

Revise this call if a public regression shows a forbidden tool can be constructed, approved, or executed after a restricted fork revives, if an empty list regains wildcard behavior, or if the project changes the documented parent-supplied boundary.

Watch next. Watch for public end-to-end resumed-fork tests across MCP reconnects and for a project-controlled policy layer that can enforce the same restriction independently of a parent model’s request.

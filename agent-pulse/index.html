Audit whether every remembered approval still names its authority

Two fresh public source changes support one bounded operator audit: follow one session-level approval through your agent stack and verify that it remains tied to a concrete command, tool, server, domain, or request. Microsoft Agent Framework now narrows an otherwise bare session approval to the triggering request or a one-shot decision; Hermes adds an alternate human-approval transport whose reply is bound to a host-created request and fails closed when it is stale, invalid, or unavailable.

Today's Action

Audit / Cross-project claim
action

Audit whether every remembered approval still names its authority

What changed. The Microsoft integration derives command identifiers for shell prompts, server and tool for MCP prompts, and a domain for unambiguous URL prompts; unsupported and parser-ambiguous cases become one-shot approval. Hermes presents an immutable request with an ID, digest, allowed choices, and timeout, then rejects mismatched, disallowed, late, failed, or missing responses rather than letting the transport decide policy.

Why it matters. An approval is often displayed in one component and consumed later in another. If the remembered decision carries only a generic yes, a changed tool identity, a malformed URL, or a substituted response can turn user intent into an unclear authority boundary. Naming the object gives an operator a concrete test before an integration gets more automation.

Claim coverage / complete 27 / 27

Operator or builder of an agent system that can remember approvals for a session or send approval prompts to another UI 20–40 minutes

Trace one approval to its exact scope

In a disposable environment with a harmless read-only or no-op tool, trigger one approval and record the request identity, the exact command, server-and-tool, or domain it covers, the permitted lifetime, and the response correlation check. Repeat with a cancelled, delayed, or malformed response. Keep the test one-shot if the system cannot derive an unambiguous scope; do not broaden permissions or use production credentials.

Two fresh public implementation receipts from distinct projects, their surrounding source and focused tests agree on a narrow authority-binding pattern. The call is about a bounded audit, not a claim that the projects share a protocol or that either implementation is deployed.

Limit

These main-branch source receipts do not prove a release, production deployment, third-party UI authentication, independent security review, or behavior in other agent runtimes. They also do not establish that Microsoft Agent Framework and Hermes coordinate or implement a common standard.

What would change this

Revise this call if public integration tests or regressions show that an approval transport can authorize a different request after a valid-looking reply, that a parser-ambiguous URL obtains persistent domain approval, or that an explicitly documented path deliberately treats a generic session approval as safely unscoped.

Watch next. Watch for release notes and adversarial integration tests that cover stale replies, changed tool identities, transport authentication, and ambiguous URL handling across a real multi-component approval path.

OpenWork removes the read-only ceiling on saved Workflows

OpenWork has merged support for connection tools and writes in live and unattended Workflows. A procedure that worked interactively can now reach those capabilities through the saved execution path too.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Watch / Project-specific claim
watch

OpenWork removes the read-only ceiling on saved Workflows

What changed. The October 3 UTC change removes the Den-only, read-only filter from live authoring and Workflow execution. Required capabilities must still be present, and tool dispatch uses the runner's authority. An App-bound live Workflow is labelled read-only only when all its declared capabilities are OpenWork reads.

Why it matters. A saved procedure can now include external work, such as a connected service operation, instead of failing because that tool disappears from the live tool tree. App authors also need to account for the resulting permission prompt.

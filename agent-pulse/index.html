Watch whether Mastra gives every concurrent approval a durable destination

Mastra’s open core pull request #20347 supports a focused watch for teams that use approval-gated agent workflows: follow whether its per-tool-call suspension identity and serialized resume path merge and receive a public distribution note. The public proposal addresses a real control boundary—two sibling workflow calls can otherwise overwrite each other’s suspension state or race the same parent snapshot—but it remains a proposal under review, not an established guarantee.

One decision-worthy insight. Action, effort, and rollback. 26 / 26 included projects monitored. Methodology ›

Today's Action

Watch / Project-specific claim
watch

Watch whether Mastra gives every concurrent approval a durable destination

What changed. The proposed code carries a suspended inner workflow run ID with each tool call, keys suspension data by tool-call ID, and queues resumes for a shared parent run. Its regression test exercises two suspended workflow tools when approvals arrive forward, reverse, and at once, expecting both calls to complete without stream errors.

Why it matters. A human approval is only meaningful when the system can associate it with the operation that asked for it. If workflow tools share a suspension record, an interface may make careful approval look reliable while a fast second click routes to the wrong run or resumes stale state.

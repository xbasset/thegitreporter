Test whether a superseded approval can still receive an answer

Cline's fresh session-lifecycle fix supports one bounded test for teams that let users edit, restart, or switch agent work: replace a run while a tool approval is pending, then verify the old request is explicitly denied and cannot consume the replacement run's reply.

Today's Action

Test / Project-specific claim
action

Test whether a superseded approval can still receive an answer

What changed. Cline clears pending interactions before starting an edited replacement session. Its interaction coordinator resolves a pending question so the outgoing run can unwind and resolves a pending tool approval as denied while recording the lifecycle reason. The merged pull request identifies the previous failure mode as a parked resolver that could intercept later answers.

Why it matters. An approval is a decision attached to a particular execution context, not a durable UI ornament. If superseded work can keep a pending resolver, an operator may see a new conversation while an old run remains suspended or receives the next answer. A disposable lifecycle drill can expose that mismatch before it becomes a support or control failure.

Claim coverage / complete 25 / 25

All 25 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builder or operator of an agent client with editable conversations or task switching 15–20 minutes

Run one superseded-approval drill

In a disposable workspace, pause a tool request for approval, edit or restart the originating prompt without answering it, then send an answer to the replacement run. Confirm that the old approval receives an explicit denied or cancelled result, its task unwinds, and the new run alone receives the later answer. Keep the test free of production credentials and destructive tools.

What would change this

Revise this call if a public regression shows an edited or superseded Cline session retaining a resolver that can accept a later reply, if the implementation intentionally preserves a pending approval across replacement sessions, or if an end-to-end test reveals another lifecycle path that bypasses cleanup.

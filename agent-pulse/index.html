Agent Pulse / Daily decision brief / 2026-08-24

Watch whether every delegated Hermes task now receives the repository’s working rules

Hermes Agent has moved workspace context from a review-specific path into its shared child-prompt builder. Teams that depend on repository instructions should watch one harmless delegated task: does the child receive the same project conventions as its parent, while an empty or ambiguous workspace stays empty rather than inheriting a guessed directory?

One decision-worthy insight. Action, effort, and rollback. 27 / 27 included projects monitored. Methodology ›

Today's Action

Watch / Project-specific claim
watch

Watch whether every delegated Hermes task now receives the repository’s working rules

What changed. The fresh public commit routes the parent’s resolved workspace path through `build_context_files_prompt` for every `delegate_task` child, including reviewers. It uses the existing priority order for `.hermes.md`, AGENTS.md, CLAUDE.md, and `.cursorrules`, deliberately skips SOUL.md, removes a review-local duplicate loader, and adds real-filesystem, empty-workspace, and reviewer end-to-end tests.

Why it matters. Delegation is a behavioral boundary: a parent can follow a repository’s conventions while a child silently works without them. The suggested check is limited and reversible. It is not a claim that the commit has shipped in a release, that every external agent follows the same convention, or that a context file makes a delegated action safe.

Claim coverage / complete 27 / 27

All 27 included projects and all 13 core coding agents have fresh source receipts for this edition.

Maintainer or operator of a Hermes Agent workflow that delegates review or implementation work inside repositories with project instructions 10–20 minutes in a disposable repository

Observe one harmless child task at the context boundary

In a disposable repository, place one non-sensitive, testable instruction in the project’s normal context-file chain. Ask a parent task to delegate a harmless check that requires that instruction, then repeat in an empty or explicitly unrelated workspace. Record whether the child follows the project rule only in the resolved workspace; do not use the result to infer access, authorization, or release availability.

Confidence / developing

The fresh public commit and inspected delegation implementation agree that the change broadens repository-context loading to delegated children. The call remains a watch because the sources are main-branch implementation and tests, not a released or independently reproduced workflow.

Limit

The receipts do not establish release availability, the behavior of a particular deployed Hermes installation, whether every supported context file is safe to inject into every task, or whether a child will correctly apply a rule once it receives it.

What would change this

Revise or withdraw the call if a public regression shows a delegated child omitting a resolved project context, loading context from an unrelated or bare working directory, or a release note narrows the feature away from ordinary delegate_task children.

Watch next. Watch for a released integration test that demonstrates parent and child behavior across a real repository, a no-workspace invocation, and a reviewer task without exposing sensitive project instructions.

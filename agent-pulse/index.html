Watch whether a repository cleanup hook survives the real retirement path

What changed. The new Factory retirement coordinator serializes cleanup for each session, attempts the linked repository's teardown command before remote release or local destruction, and then continues with scrub, pooling or destruction, cache invalidation, and optional session deletion. Its tests require the hook to run before scrub/pooling/invalidation, continue cleanup after a failing hook, and avoid duplicate teardown under concurrent retirement requests.

Why it matters. A generic reset cannot know every project-specific service, generated artifact, or checkout convention. But a project hook is not an integrity proof either: it can fail, hang, or be incomplete. The useful operational question is whether the platform preserves its independent recovery invariants after that hook reports trouble, rather than whether a cleanup script exists.

Do not use a teardown command that deletes broad filesystem paths or production credentials.

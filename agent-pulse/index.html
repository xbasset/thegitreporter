Audit nested resume before you call an agent workflow durable

Microsoft Agent Framework’s Python workflow repair now persists a sub-workflow checkpoint inside the parent executor, so a resumed parent can restore nested mid-progress state instead of only replaying pending request information.

Today's Action

Audit / Project-specific claim
action

Audit nested resume before you call an agent workflow durable

What changed. The change adds checkpoint-object capture and restore for nested workflows, embeds sub_workflow_checkpoint on save and restore, retains a reader for older checkpoints, and moves request and response tracking back to the shared sub-workflow that actually owns it. Public regression tests cover the nested capture-and-restore path.

Why it matters. Approval-gated and long-running agent workflows can look resumable while the child that holds their active context has not really returned. Auditing state ownership before adding a resume control can prevent repeated work, improvised recovery, and a misleading operator status signal.

Claim coverage / complete 25 / 25

All 25 included projects and all 13 core coding agents have fresh source receipts for this edition.

Agent-workflow builder 30–45 minutes for one workflow

Draw the checkpoint boundary

For one nested workflow, list the parent status, child context, pending request correlation, and any tool state. Then identify which exact object is persisted and which object restores each field after a restart.

Reversible
Agent-platform tester 60–120 minutes per recovery path

Prove a child returns

Add a restart test that pauses a child workflow mid-progress, captures the parent checkpoint, restores it in a fresh process, and asserts that the child retains its expected state without repeating an external effect.

Reversible

Shows the nested checkpoint capture and restore mechanism, the backward-compatible read path, the state-ownership correction, and the public regression tests that define the intended source-level contract.

Confidence / strong

The public commit description, implementation change, and new nested workflow tests agree on a narrow project-scoped recovery contract. The conclusion stays confined to Microsoft Agent Framework’s Python source rather than treating one repair as a field-wide reliability result.

Limit

This receipt establishes an inspected source and test change, not release inclusion, production deployment, every storage backend’s behavior, or idempotence of model-provider and external-tool effects after a restart.

What would change this

Revise this call if later source removes the nested checkpoint path, shows the restored child loses its active state, demonstrates duplicate effects across the restart boundary, or limits the change to a non-default test-only workflow path.

Watch next. Watch for a released integration test that pauses a nested workflow across a real approval, callback, or tool boundary and demonstrates both state recovery and duplicate-effect prevention.

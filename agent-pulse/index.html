Check which MCP implementation owns your Pi session

Pi v0.99 supplies MCP as a replaceable built-in extension. Existing adapters can retain the session command, while newer adapters can choose separate command and configuration names.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Test / Project-specific claim
action

Check which MCP implementation owns your Pi session

What changed. An extension registering /mcp displaces the built-in session integration. Nested tool calls can use common validation and call/result hooks; standalone pi mcp shell commands still use the built-in implementation.

Why it matters. An upgrade can offer useful default connections without forcing the same ownership arrangement on every existing extension-based workflow.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Pi users upgrading a setup with an MCP extension One isolated session before migrating the working setup

Try one disposable read-only connection

With a copy of the current configuration, identify which extension owns the session command, connect one read-only test server and check the expected tool and result hooks. Keep the previous setup available until the adapter and Pi versions work together.

Receipt 1 / earendil-works/pi / release / September 29, 2026 Pi v0.99.0 supplies replaceable built-ins

Publishes MCP, Code Mode and tool search with public nested-execution mechanisms.

 Receipt 2 / earendil-works/pi / docs / September 29, 2026 Versioned replacement and SDK contract

Documents session command ownership, the shell-command exception and explicit SDK extension loading.

Confidence / developing

Release documentation, implementation and regression definitions agree on replacement and nested-call mechanisms.

Limit

We inspected code and test definitions, not a live MCP integration. Adapter configuration migration does not prove compatibility between released versions; the VM does not confine invoked host tools.

What would change this

A pinned release reproducer showing that the built-in connects a server despite replacement by an installed /mcp extension would contradict this ownership contract.

Watch next. An extension migration that preserves command ownership, policy hooks and tool results against the released Pi interfaces.

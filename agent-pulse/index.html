A live trust change needs a session boundary, not a wish

Qwen Code's public workspace-trust hot-reload change treats a changed trust policy as a runtime transition: it rebuilds workspace generations, reports reconciliation state, and makes affected daemon routes fail closed rather than leaving an existing task to continue against an ambiguous policy.

Today's Action

Audit / Project-specific claim
action

A live trust change needs a session boundary, not a wish

What changed. The source adds a daemon trust-policy monitor and reconciler, generation guards around workspace runtime work, route-level untrusted and generation-closed responses, and focused tests for policy changes, drains, retries, and in-flight state. That is an implementation contract for Qwen Code source, not evidence that every deployment has it.

Why it matters. Agent operators often treat a folder-trust or permission edit as a quiet configuration update. If a task, session, or tool route can outlive the change, the old authority may continue invisibly. A named generation boundary gives a system a place to stop, rebuild, and explain what changed before it performs more work.

Agent-platform builder 30–45 minutes per runtime

Audit a live policy change

While a non-sensitive agent task is active, change one workspace trust or permission rule and verify that every tool route either receives the new policy through an explicit generation transition or fails closed with a visible reason. Capture the session, tool, and retry behaviour.

Reversible
Qwen Code evaluator 20–30 minutes

Test the source boundary before relying on it

Use an isolated test workspace to compare a trust-policy change before and during a task. Confirm that the observed build and configuration match the public source change, then check whether a blocked request and a clean restart leave an understandable audit trail.

Limit

What would change this

Revise this call if later source or tests show that a trust change can leave an old generation performing a tool action without an explicit policy check, if the guard is bypassed on a supported route, or if the change is reverted before release.

Watch next. Watch for a tagged release and a public end-to-end test or operator report that changes trust during an active session and records the exact blocked, drained, restarted, and audit-visible outcomes.

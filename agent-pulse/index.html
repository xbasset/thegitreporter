Agent Pulse / Daily decision brief / 2026-08-03

Audit the compiled path before trusting an agent-workflow check

Pydantic AI’s fresh workflow-policy guard supports one bounded audit for teams that run coding agents in GitHub Actions: inspect the generated workflow graph for conditions that read undeclared dependencies, and confirm that the compiled file—not just the editable prompt source—changes with the intended policy. The project’s source-level change encodes historical cases where an agentic workflow could skip while the required check still appeared successful.

One decision-worthy insight. Action, effort, and rollback. 26 / 26 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit the compiled path before trusting an agent-workflow check

What changed. The guard parses the workflow that Actions actually runs and rejects `needs.<job>` expressions that do not name declared dependencies, source changes without a regenerated lock, unreachable agent prompt paths, mismatched timeout budgets, and other configuration shapes that can turn intended agent work into a silent no-op. The focused regression suite reconstructs the broken dependency graph and expects an actionable violation.

Why it matters. A prompt can be sound while the compiled configuration never schedules the agent, gives it an unusable workspace path, or runs an older lock. Checking the execution path is a reversible way to distinguish a passing status from evidence that the intended agent job was reachable.

Claim coverage / complete 26 / 26

All 26 included projects and all 13 core coding agents have fresh source receipts for this edition.

Maintainer or platform engineer operating coding-agent workflows in GitHub Actions 20–30 minutes

Trace one agent check from source to compiled graph

In a disposable branch or checkout, choose one agent workflow and compare its human-edited source with the generated workflow that Actions executes. For every `needs.<job>` used in a condition or interpolation, confirm that job is declared as a dependency; then make a harmless source-only change and verify the required generated artifact changes with it. Do not use production credentials or trigger destructive agent tools for this audit.

Limit

These are source-level receipts from Pydantic AI. They do not establish that a particular hosted workflow, release, or agent run completed, nor do they prove that another agent platform has the same compilation and skipping behavior.

What would change this

Revise this call if public GitHub Actions semantics show that an undeclared `needs` reference fails loudly rather than resolving empty in the covered positions, if the generated lock is not the artifact Action executes, or if Pydantic AI removes the guard in favor of a demonstrably equivalent check.

Watch next. Watch for end-to-end workflow fixtures that prove a real agent job starts, receives the intended context, and emits a bounded result after the static guard passes.

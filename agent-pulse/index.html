Before adopting Kilo’s new board default, separate a stored note from a task control

Kilo’s September 14 source change enables the shared agent board by default and lets an explicit opt-out win. Operators evaluating that change should check what their coordination logic treats as success: a stored post does not establish that another agent read it, acted, or stopped.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Before adopting Kilo’s new board default, separate a stored note from a task control

What changed. The board resolver enables the feature unless its configuration or specific environment flag explicitly disables it. The board’s documented contract separates message storage from task execution: posts do not wake or resume recipients, and HOLD/VETO notes do not pause or cancel work.

Why it matters. A team can appear to coordinate while waiting for a finished worker or assuming an advisory message halted a conflicting edit. The new default makes these semantics relevant to operators who did not previously opt into the board.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Operators testing Kilo’s default-on shared board source change 15–20 minutes for one disposable session

Audit one stopped-recipient exchange

In a disposable session on a build containing the default-on change, complete a child task and post a follow-up. Confirm the returned recipient state and that the task remains completed. Check the installed version and explicit opt-out settings before applying any default assumption to a working environment.

 Receipt 2 / Kilo-Org/kilocode / docs / 2026-09-14T17:58:10+02:00 Kilo Swarm’s documented communication boundaries

The settings documentation states that posts are stored messages, notices are best-effort, recipients are not a privacy boundary, and HOLD/VETO are advisory rather than execution controls.

Confidence / strong

The changed default resolver, its explicit-disable tests, current tool implementation and public settings documentation agree on the narrow source behavior. Live agent compliance was not tested.

Limit

This is a source-level change. At the September 15 reporting check, the latest published v7.6.2 still documented opt-in behavior. The source does not establish rollout, receipt by a model, or whether a model obeys the coordination instructions.

What would change this

Revise the call if a subsequent implementation makes posting a task-control operation with verified delivery or acknowledgment, or if the default-on change is reverted before release.

Watch next. Watch for a release carrying the September 14 default and tests showing how models handle stopped-recipient warnings and advisory hold messages.

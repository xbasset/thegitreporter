Studio adds an inference-engine choice beside the model choice

Unsloth has merged optional vLLM and SGLang engines into Studio. A local model can now have a remembered engine and GPU layout, giving operators a concrete serving configuration to compare.

Today's Action

Watch / Project-specific claim
watch

Studio adds an inference-engine choice beside the model choice

What changed. The October 2 implementation installs engines on demand in separate environments, manages their processes and forwards requests to their native APIs. The engine adapter maps tensor, pipeline and replica modes to different launch arguments. Selecting Default returns to the existing backend.

Why it matters. Splitting a model across GPUs and replicating it for concurrent requests solve different problems. The new controls expose that choice inside the same application.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Teams evaluating Studio on supported NVIDIA hardware One version check followed by a bounded serving comparison

Watch for a containing build and a matched workload

Check that the build contains the managed-engine change, then compare the same model and request set on Default and one optional engine in a disposable profile. Record GPU allocation, concurrency and completed responses before changing an existing deployment.

 Receipt 2 / unslothai/unsloth / docs / October 2, 2026 Pinned optional inference-engine contract

Confidence / developing

The merged adapter, documentation and regression definitions agree on the new configuration choice; no live GPU comparison was run here.

Limit

This is source-level capability, not a verified release installation, throughput gain or model-quality improvement. Compatibility depends on hardware, model and pinned engine versions.

What would change this

A pinned supported build that fails to preserve the selected engine or launches a different parallelism mode would contradict this reading.

Watch next. A containing release and reproducible same-model serving results that include installation and memory costs.

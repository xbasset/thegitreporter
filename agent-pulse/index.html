Audit agent diagnostics for signed URLs before widening egress

OpenClaw's fresh redaction change supports one bounded audit for teams operating agent tools: inspect the diagnostic paths that may serialize URL query strings and form-like request bodies before treating those logs as safe to retain or share. The public patch adds signed URL and X-prefixed authorization names to the redaction machinery and tests both network-policy and logging paths.

One decision-worthy insight. Action, effort, and rollback. 25 / 25 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit agent diagnostics for signed URLs before widening egress

What changed. The change moves URL credential masking toward shared query-pair classification, recognizes sig and X-prefixed authorization fields, and applies the same sensitive-key decision to URL, body, and diagnostic representations. The focused tests are evidence that these input shapes were considered; they are not proof that every plugin, proxy, exporter, or downstream log store is covered.

Why it matters. Agent systems increasingly carry browser destinations, storage links, provider calls, and gateway headers through support and observability channels. A secret that is protected at the request boundary can still leak when a URL or payload is rendered for debugging. Auditing the representations is a reversible way to find a gap before a broad egress or logging rollout makes it durable.

Claim coverage / complete 25 / 25

All 25 included projects and all 13 core coding agents have fresh source receipts for this edition.

Agent-harness operator or integrator who retains HTTP diagnostics 20–30 minutes

Run one redaction fixture drill

In a disposable test log pipeline, send representative signed URLs and diagnostic bodies using sig and X-prefixed authorization fields. Check the application log, error reporter, proxy trace, and exported support bundle for the literal values. Add a regression fixture for every representation that can preserve the request, and keep production credentials out of the drill.

Confidence / strong

One fresh, directly inspected OpenClaw commit changes both the shared redaction implementation and focused tests for the diagnostic representations described in this audit.

Limit

This is source-level evidence from OpenClaw. It does not establish a released build, coverage of every plugin or log exporter, safe retention policies, or that another agent stack uses the same redaction paths.

What would change this

Revise this call if a public regression shows the same sig or X-prefixed values survive a covered URL or body path, if the project documents an intentionally unmasked representation, or if the implementation moves the responsibility to a boundary that does not receive diagnostics.

Watch next. Watch for end-to-end fixtures covering proxy, telemetry, error-reporting, and plugin exports, where redaction failures tend to reappear after an application-level log is fixed.

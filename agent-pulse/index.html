Today's Action

Test / Project-specific claim
action

Test an AUTO-mode denial with one exact retry, not a broader exception

What changed. The change fingerprints the tool name, canonicalized parameters, and working directory. A classifier block stores that fingerprint; only a matching next call falls into manual confirmation, consumes the retry before display, and suppresses persistent approval. Changed arguments or a changed directory are reclassified, while destructive commands retain their explicit-approval guard.

Why it matters. A safety denial is useful only if the person responsible for the work can understand what is being decided. Binding the review to one identifiable action preserves human control without turning a single false positive into a broad exception for nearby commands.

Do not use destructive command examples.

Limit

These receipts establish intended source and regression-test behavior only. They do not prove a released build contains the change, that a live classifier makes consistent decisions, or that every UI and ACP path renders the review identically.

What would change this

Revise or withdraw this call if a public test or issue shows changed arguments or directories inheriting the retry, persistent approval appearing in the fallback, or destructive actions receiving the same retry invitation.

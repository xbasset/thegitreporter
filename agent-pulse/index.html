Agent Pulse / Daily decision brief / 2026-08-18

Audit workflow cache keys before pinning agents to review worktrees

Qwen Code's merged workflow change treats an existing linked worktree as part of a subagent dispatch and includes that directory in the workflow journal identity. Builders who resume or cache workflow-agent work across review branches should audit whether their own harness records the workspace identity, rather than assuming the prompt alone identifies what was inspected.

One decision-worthy insight. Action, effort, and rollback. 27 / 27 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit workflow cache keys before pinning agents to review worktrees

What changed. The public commit adds `workingDir` for workflow agents, routes a pinned agent away from a path that would leave it on the parent configuration, validates the directory as a registered linked worktree of the same repository, and adds `workingDir` to canonicalized journal options. The documentation distinguishes this caller-owned pin from fresh worktree isolation and rejects the conflicting pair in workflows.

Why it matters. A reusable answer is unsafe when the same task text can be asked against two different uncommitted trees. The bounded action is an audit of dispatch identity and cache behavior, not a claim that a particular Qwen Code release or every agent workflow has a wrong-tree defect.

Claim coverage / complete 27 / 27

All 27 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builder or operator maintaining a resumable workflow-agent harness 30–60 minutes for a disposable two-worktree reproduction and cache-key inspection

Check that workspace identity participates in resume and cache keys

In a disposable repository with two linked worktrees that differ in one harmless fixture, run the same read-only review prompt once per tree. Inspect only redacted local diagnostics to confirm that the second run cannot reuse the first tree's answer. If the harness supports a caller-owned worktree option, also verify that it rejects a contradictory request to create a separate isolated worktree. Do not run the test against a production branch or sensitive checkout.

Limit

The receipts are merged source and documentation. They do not establish that the change is released, that a wrong-tree incident occurred, or that another workflow system uses the same worktree and resume semantics.

What would change this

Revise or withdraw the call if a public reproduction shows that Qwen Code's workflow resume key excludes the bound worktree after this change, or if its documented workflow path safely canonicalizes an equivalent caller-owned tree without recording the directory in dispatch identity.

Watch next. Watch for a release note or a public issue that runs the workflow path against two real linked review worktrees and documents the resulting cache or resume behavior.

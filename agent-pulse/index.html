Treat cancellation as a separate contract from typed agent output

PydanticAI has added a cancellation backstop for a durable run whose awaited activity or hook absorbs an external cancellation. Its fresh source and test work make a practical project-scoped call: if an agent can start long-running work, audit whether its completion path can still distinguish a valid result from a cancellation that a lower layer consumed.

One decision-worthy insight. Action, effort, and rollback. 24 / 24 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Treat cancellation as a separate contract from typed agent output

What changed. The inspected implementation re-checks Python's pending cancellation state at agent-run step and hook boundaries after completed messages have been recorded. The public hardening follow-up says this is a policy signal rather than proof of outside intent, while the Temporal-focused test models an activity that absorbs cancellation and requires the workflow to end cancelled and replay its history.

Why it matters. Typed dependencies, tool arguments, and structured output can constrain the data an agent exchanges, but they do not establish whether an asynchronous run was interrupted safely. A system that lets cancellation turn into success can schedule follow-on work, show a misleading completion, or run the wrong cleanup path even when every value passing through its schema is valid.

Builder of durable agent workflows 30–60 minutes

Audit one cancellation boundary

Choose one run that awaits a model stream, tool activity, or event handler. In a non-production test, cancel it while the awaited component catches cancellation and returns normally; verify that the top-level run reports cancellation, records already completed work distinctly, and cannot run downstream success hooks.

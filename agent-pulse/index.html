Test whether approval replies can get through a busy desktop app

OpenWork’s September 16 change isolates finite desktop permission replies from renderer event-stream pressure. A local test distinguishes a blocked approval request from slow model inference.

Today's Action

Test / Project-specific claim
action

Test whether approval replies can get through a busy desktop app

What changed. Long-lived HTTP/1.1 event streams can occupy Chromium’s per-origin connections. Selected permission POSTs now use the existing main-process Node loopback transport, preserving deadlines and cancellation without automatic replay.

Why it matters. A responsive permission button does not prove that the engine received the user's decision. Supervision depends on transport capacity as well as visible controls.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builders maintaining Electron interfaces for local software agents 30–60 minutes with an existing transport fixture

Separate decision delivery from resumed inference

In an isolated fixture, hold event streams open and delay final inference. Check whether an approval reaches the engine exactly once, resolves only its request and preserves cancellation. Confirm the installed build contains the source change before expecting the new path.

 Receipt 2 / different-ai/openwork / runtime-test / 2026-09-16T22:49:12Z Permission pressure regression

Assertions distinguish zero wire replies on baseline from a completed local read while final inference remains held and an unrelated permission stays pending.

Confidence / strong

Source, regression assertions and the public investigation agree. Our run of eight standalone transport tests passed; the complete Electron scenario was inspected, not rerun.

Limit

The reproduction does not establish the cause of the uninstrumented installed incident or certify every control under pressure. The latest listed OpenWork release predates the merge, and a timed-out reply may already have been applied.

What would change this

Revise the call if the selected local path still shares the pressured Chromium connection pool, loses request scoping, or a subsequent change reverts the isolation.

Watch next. Look for a release containing the repair and pressure tests for the remaining control paths or a fix to the event-stream budget.

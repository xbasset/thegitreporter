Give delayed child approval a workflow return path

Microsoft Agent Framework now keeps unresolved child function approvals out of Agent.as_tool parent continuations, directing delayed approval to workflows.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Give delayed child approval a workflow return path

What changed. Each delegated invocation has a child session. Immediate approval middleware rules can decide inside it; unresolved child function approvals fail the call. Propagated application state excludes framework approval and budget keys, including custom middleware identifiers.

Why it matters. Showing a permission request does not establish that a later answer can resume the intended child operation. An approval that waits needs an owner for the suspended work and its return path.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Python Agent Framework developers using nested tools 20–30 minutes with an existing test application

Audit who resumes each child approval

In a disposable build containing PR #8527, identify each child tool requiring approval. Keep immediate policy inside the child; test a workflow call-and-return for a harmless request needing a later response. Verify the result returns to the intended coordinator and test checkpoint restoration separately if persistence is required.

What would change this

Today's Action

Audit / Project-specific claim
action

Check which boundary your Studio tool process actually receives

What changed. The revert removes the generic sandbox planner from Python and terminal launches. Existing software safeguards remain, and a separate account-confinement module returns no boundary for owner context while selecting confinement or refusing managed-account execution unless explicitly allowed unconfined.

Why it matters. A successful review of a previous version does not establish the boundary around the code executing on an operator’s machine.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Operators evaluating local Unsloth Studio tools 20–40 minutes with an existing test installation

Identify build and account mode

Record the installed source version and account mode. In a disposable environment, use harmless canary files to distinguish a software check from an active filesystem boundary. Compare the actual launch path with the reverted and surviving code before relying on the earlier review.

Confidence / strong

Limit

What would change this

Revise the call if a later source or installed build restores a general owner-mode isolation layer, or an independently reproduced launch shows a different boundary.

Watch next. A replacement launch boundary or explicit account-aware contract with controls proving active isolation rather than fallback.

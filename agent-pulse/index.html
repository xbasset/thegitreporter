Audit which account drives a human agent turn before enabling individual authorization

QM's public individual-authorization change gives an organization a way to route an interactive human turn through that person's connected Claude, ChatGPT, or API-key account. Before enabling a comparable path, audit one disposable human turn and one scheduled task separately: the useful question is not whether an account picker exists, but which credential and harness each origin is actually allowed to use.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit which account drives a human agent turn before enabling individual authorization

What changed. The merged source enters the individual-auth branch only when the origin is human and the organization toggle is enabled. It resolves a user-and-provider credential into a Claude, Codex, or Pi harness path, obtains derived OAuth material from the keychain, and refuses a human turn with no connected account rather than silently using the organization credential. The public change states that automation, cron, and ambient turns remain on the organization path.

Why it matters. A company can host an agent service while a person supplies the subscription or API account that powers an interactive turn. That split can change billing, consent, incident review, and credential-revocation decisions, but only if background work is not casually assumed to inherit the same identity. The source supports a bounded audit of the route; it does not establish deployment behavior, provider billing, or a privacy guarantee.

Operator or security owner evaluating a per-user AI-account feature in an organization-hosted agent service 20–40 minutes in a disposable environment

Trace one human turn and one background task as separate credential paths

In a disposable environment, connect a non-production account for one test user and record the selected harness and credential boundary for one interactive human turn. Then trigger one harmless scheduled or ambient task and verify its documented organization-level path separately. Confirm that a human turn without a connection fails visibly instead of borrowing a shared credential, and do not infer broader privacy or billing behavior from this single exercise.

Confidence / developing

The merged commit, routing code, and focused public test fixtures agree on an opt-in human-turn route and on a separate organization path for background origins. They are source-level receipts, so the recommendation remains a reversible audit rather than a claim about a live deployment.

Limit

The public receipts are main-branch implementation and fixture-based tests. They do not establish release availability, an external security audit, a particular organization's retention or billing policy, provider behavior, or the outcome of every OAuth, keychain, harness, or scheduled-task failure.

What would change this

Revise or withdraw this call if public source or a regression shows a human turn without a connected account silently falling back to organization credentials, a user credential crossing into another user's harness, a refresh token entering the child boundary, or automation unexpectedly taking the individual-auth path.

Watch next. Watch for public operational guidance that names the audit, logging, revocation, and failure behavior for an interactive personal-account turn versus a retry, cron, monitor, or ambient task.

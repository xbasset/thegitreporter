Agent Pulse / Daily decision brief / 2026-08-08

Audit whether an agent can rewrite the instructions that will steer its next session

Hermes Agent's fresh protected-instruction write gate supports one bounded audit for people operating coding agents in shared repositories: inventory the project files that can become later agent instructions, then check whether changing each one requires a fresh human decision rather than inheriting an earlier broad approval. The inspected source distinguishes those high-leverage persistence targets from ordinary working files and refuses the protected write when no human approval channel exists.

One decision-worthy insight. Action, effort, and rollback. 26 / 26 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit whether an agent can rewrite the instructions that will steer its next session

What changed. The public implementation matches normalized and real paths for AGENTS.md, CLAUDE.md, SOUL.md, .cursorrules, and immediate project-local .hermes configuration. It uses a separate one-operation approval path rather than the ordinary yolo or session-persistent gate, treats one protected target as a stop for a whole multi-file patch, and includes focused tests for traversal, symlinks, repeated writes, and no-human failure.

Why it matters. A permission that is reasonable for editing application code can be too broad for changing material that a later agent session treats as instruction. Separating an ordinary file edit from a persistence-changing edit gives operators a concrete review point before one task silently changes the next task's starting conditions.

Claim coverage / complete 26 / 26

All 26 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builder or operator who lets coding agents edit shared repositories 20–30 minutes

Trace one instruction-file write path

In a disposable clone with no production credentials, list every project-controlled file your coding agent can load as instructions, settings, skills, or prompt context. Attempt a harmless edit to one such file and verify that the exact write path requires fresh, one-time human approval even when ordinary edits are auto-approved. Test a symlink or normalized-path variant only in the disposable clone; do not use the drill to modify a live policy file.

Limit

These are public source and test receipts from Hermes Agent main. They do not establish a released version, independent security testing, coverage of every terminal or tool write route, all instruction loaders, or prevention of every prompt-injection vector.

What would change this

Revise this call if a public regression shows that a protected project instruction file can be rewritten through the covered write or patch paths without a fresh prompt, if an inherited auto-approval bypasses the separate gate, or if the documented scope excludes a named file the tool loads as project instruction.

Watch next. Watch for public end-to-end adversarial tests that carry a protected write attempt through later instruction loading, terminal execution, and another agent session; those tests will show how far the narrow file-tool boundary reaches.

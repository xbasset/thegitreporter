Check that Stop survives a Gateway restart

OpenClaw now saves cancellation of a parent waiting for background children before answering Stop, so restart recovery can respect the user's decision.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Test / Project-specific claim
action

Check that Stop survives a Gateway restart

What changed. A yielded parent has no active run controller. The session-abort handler captures its identity, cancels descendants and persists the parent's terminal state before responding, with guards against overwriting a newer turn or reset session.

Why it matters. Stopping a child does not by itself tell recovery that its waiting parent must stay stopped. A restart can otherwise revive work the operator cancelled.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Operators testing OpenClaw delegated tasks 20–30 minutes with an existing test installation

Test the stop acknowledgment across restart

On a disposable Gateway containing PR #153271, start a harmless parent that yields to a child. Stop it, wait for the response, restart the Gateway and inspect both states. Check any incomplete-cancellation error separately; do not infer every child stopped from the parent's terminal state.

Evidence Chain

2 direct receipts
Receipt 1 / openclaw/openclaw / commit / Sep 20, 03:51 AM GMT+2 Persist the yielded parent's cancellation before the Stop response

The handler and regression cases cover durable parent cancellation, restart, newer-turn and reset races, and partial descendant cancellation.

 Receipt 2 / openclaw/openclaw / pull-request / September 20, 2026 Reported live Stop and restart reproduction

The merged PR reports the original Control UI failure and a repaired model-backed parent/child test across an actual Gateway restart.

Confidence / strong

Merged code and regression cases agree with the contributor's reported live restart reproduction; the call is limited to this source-level mechanism.

Limit

We did not independently run the live reproduction or map the fix to a released package. Parent cancellation can coexist with an incomplete descendant-cancellation error and does not undo completed external actions.

What would change this

Revise the call if a build containing the repair acknowledges Stop for the captured yielded parent but restart recovery resumes that same cancelled run, or a later patch changes the persistence contract.

Watch next. A released build and operator reproduction preserving both the parent's terminal state and honest child-cleanup errors across restart.

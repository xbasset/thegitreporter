Audit whether a denied agent response can still reach session history

Microsoft Agent Framework's fresh experimental Agent Hooks work supports one bounded audit for teams that apply policy after model or tool work begins: trace a rejected response through both the user-facing stream and the state a later turn can load. Its source change puts verdict-gated persistence beside the output gate, so the intended question is not only whether a deny hides text now, but whether the denied text becomes durable context later.

One decision-worthy insight. Action, effort, and rollback. 26 / 26 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit whether a denied agent response can still reach session history

What changed. The public implementation joins agent, model, and function interception as one middleware bundle, fails closed on enforcement-layer errors, buffers streams until the relevant verdicts have run, and defers the covered history write until that verdict permits it. Its focused tests include denied streams, denied output without durable history, transformed output persistence, and retries. The source also documents that provider-hosted tools do not take the direct function-invocation path.

Why it matters. An agent's session memory is part of its future authority: text that is blocked at egress but retained in history can still shape a later model call, handoff, summary, or operator review. Auditing both boundaries gives a team a testable way to distinguish a visible moderation result from actual containment of the rejected material.

Claim coverage / complete 26 / 26

All 26 included projects and all 13 core coding agents have fresh source receipts for this edition.

Framework builder or operator responsible for agent policy and session persistence 30–45 minutes

Run one deny-to-memory test

In a disposable environment with non-sensitive prompts, cause one post-model or output policy deny. Verify separately that no partial stream reached the client and that the next run, session reload, summary, or delegated task cannot retrieve the denied material. Repeat after one retry path. Record any provider-hosted tool path that bypasses your direct tool interceptor; do not infer coverage from a visible deny alone.

Limit

What would change this

Revise this call if public regression evidence shows that a denied response still enters the covered history provider or a later session reload, if stream data escapes before the output verdict, or if the documented hosting boundary is materially broader than the source currently states.

Watch next. Watch for a released integration, a current-draft conformance report, and tests that demonstrate how provider-hosted tools and long-lived nested sessions interact with the persistence gate.

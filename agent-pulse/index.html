Pi can store the wait while the host supplies the wakeup

Pi’s experimental durable harness has merged sleeping task state and a host wake contract. The inspected changelog still lists the change as unreleased after v1.3.0.

Today's Action

Watch / Project-specific claim
watch

Pi can store the wait while the host supplies the wakeup

What changed. A sleep commits an absolute deadline and next checkpoint, ending its invocation. With onWake configured, a host alarm resumes due work; the default Node timer instead keeps the process alive.

Why it matters. Integrators can design delayed or polling work that survives process eviction, but adoption includes host alarm ownership and a storage compatibility change.

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Prepare one delayed-task trial on disposable storage

Wait for a containing release, then copy a test dataset and verify a stored deadline across eviction, alarm-driven resumption and a retry-safe external action. Keep the original database untouched: the new SQLite schema cannot reopen under v1.3.0 or earlier.

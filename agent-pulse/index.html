Agent Pulse / Daily decision brief / 2026-08-04

Audit whether your agent manager treats recovery state as its control API

Kilo Code’s fresh Agent Manager patch supports one bounded audit for teams operating parallel coding agents: identify any file that stores live panel or recovery state, then verify agents change it only through an inventory-backed controller operation rather than direct edits. The public patch adds a list-first move operation for an agent’s worktree and rejects direct writes to the named manager state files.

One decision-worthy insight. Action, effort, and rollback. 26 / 26 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit whether your agent manager treats recovery state as its control API

What changed. The new contract requires the caller to obtain live section and session IDs through `action: list`, then pass those IDs to a targeted `action: move`; `sectionID: null` ungroups a worktree. The implementation validates the session and target section, while the write/edit/apply-patch guard refuses direct edits to the persisted manager state. Focused tests establish intended source behavior, not every recovery or concurrent-update outcome.

Why it matters. A stale or invented identifier can reorganize the wrong live worktree, and a convenient state-file patch can collide with a controller that is persisting or restoring the panel. Separating the inventory, mutation API, and recovery file makes a multi-agent controller easier to audit before more automation is allowed to operate it.

Claim coverage / complete 26 / 26

All 26 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builder or operator of a multi-agent coding workspace 20–30 minutes

Trace one live-state mutation

In a disposable workspace, choose one agent-manager action that changes live organization or task state. Identify the controller’s read API, its target validation, and the persisted UI/recovery files. Confirm the agent can obtain current identifiers only from the controller and cannot write the persisted state file directly; add one regression test for a stale, unknown, or non-assignable target. Do not use production credentials or modify a live work queue during the drill.

Confidence / strong

Limit

These are public source receipts from Kilo Code. They do not establish a released extension version, adoption, safety of every restore or concurrent-update path, or that another agent manager stores and protects state the same way.

What would change this

Revise this call if a public regression shows an agent can directly mutate the protected manager state, if a list-derived move targets a different live worktree after a concurrent update without detection, or if the persisted file is documented as the supported control API.

Watch next. Watch for end-to-end recovery and concurrent-update tests that move a worktree while panel state is saved or restored; that is where the boundary will prove durable or expose a race.

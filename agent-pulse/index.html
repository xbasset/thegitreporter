Audit inherited session credentials before a child process inherits an agent inbox

Qwen Code's public main-branch change treats QWEN_CODE_MESSAGING_SOCKET and QWEN_CODE_MESSAGING_TOKEN as one capability. Operators building from this source or analogous runtimes should run a disposable nested-child check: a child that has not bound its own inbox must not retain either inherited value, while a child that binds a new inbox should receive only its own fresh pair.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Audit inherited session credentials before a child process inherits an agent inbox

What changed. The source adds a per-session token beside the inbox address, requires it before any incoming frame is read, carries a token on return receipts, and clears an inherited socket-and-token pair at the CLI entry point before any route can spawn a child. Focused tests cover malformed and wrong tokens, inherited-pair scrubbing, fresh-pair publication, and the fast paths that bypass the ordinary startup route.

Why it matters. A reachable local endpoint plus its valid credential can let a child or lifecycle script speak to an ancestor session. Auditing both values as one capability is a bounded way to catch an ownership leak before treating local cross-session messaging as a safe supervisory channel.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Qwen Code source-build or fork operators, and builders of comparable child-process agent runtimes 20–30 minutes in a disposable environment

Run a disposable inherited-capability check

In a disposable environment, create one session inbox and launch a nested child that does not bind an inbox of its own. Verify that neither the inherited socket variable nor its token is present. Then launch a child that binds a new inbox and verify it receives a fresh pair that cannot authenticate to the ancestor. Do not use production credentials or live channels.

What would change this

Revise or withdraw this call if public source or a regression demonstrates that a child which has not bound its own inbox retains the ancestor socket-and-token pair after CLI entry, or can inject into the ancestor with such a pair.

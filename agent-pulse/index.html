Audit the pause path before treating a computer-use window approval as a durable grant

OpenWork’s fresh computer-use source turns a person’s selected app window, access mode, and pause control into a native session boundary. Today's Action

Audit / Project-specific claim
action

Audit the pause path before treating a computer-use window approval as a durable grant

What changed. The merged runtime fixes the approved app and mode for a session, gives observations a short lifetime and one action attempt, caches receipts by request identifier, and clears the current observation when a person pauses, types, or stops. Its public fixture then requires a fresh observation after resume and rejects a second connection that tries to reuse the grant.

Why it matters. Computer-use tooling can make one mistaken click consequential. A pause that preserves a stale screenshot or lets an orchestration layer resume without a person turns an apparent control into theater. A bounded session gives operators a concrete place to inspect scope, interruption, retry behavior, and the difference between dispatching an input and proving its result.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builders and operators piloting desktop computer-use tools 30–45 minutes in a disposable local environment

Exercise a person interruption in a disposable app

In a disposable application window with synthetic data, approve the smallest available scope, obtain an observation, then resize the window or type as the person before the next action. Confirm the tool rejects the stale observation, does not auto-resume, requires a fresh view after a person resumes, and records a dispatched action separately from verified task success.

Confidence / developing

A fresh public merge, native runtime design, and end-to-end fixture agree on the same scoped-control behavior, but the reporting did not run the macOS helper and no ordinary-workload benchmark is available.

Limit

These receipts establish a merged development-branch design and controlled test behavior, not a packaged release, a cross-platform implementation, safe handling of untrusted screen content, or proof that an approved app cannot take consequential actions.

What would change this

Revise this call if public source or tests show that a person interruption can leave an observation valid, permit automatic resume, let another connection reuse the session, or turn a retry after a lost reply into a repeated input.

Watch next. Watch for packaged-release evidence, platform-specific boundary designs, and repeatable tests in less controlled applications where focus changes, animation, and real operator interruption are common.

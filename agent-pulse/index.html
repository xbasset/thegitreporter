Audit which environment actually carries your coding agent’s permission choice

Codex’s fresh turn-environment changes support one bounded audit for teams using multiple roots, remote environments, or delegated agents: trace a single permission profile from selection through the tool that acts, then through one child or resumed task. Today's Action

Audit / Project-specific claim
action

Audit which environment actually carries your coding agent’s permission choice

What changed. One public change snapshots the permission profile into each turn environment and preserves the configuration an active turn captured; the next passes the selected environment’s permissions into shell, unified execution, patching, image viewing, network approval, Guardian context, and delegated-agent paths. The code and tests support a consistency boundary: the authority selected for work should reach the runtime doing that work. They do not turn an allowed action into a safe action or establish behavior outside the inspected source and tests.

Why it matters. In a multi-workspace or multi-agent task, a good permission UI can still mislead if a different environment executes the command or receives the child task. Treating selected environment, workspace roots, and capture time as reviewable facts gives an operator a specific place to detect authority drift before it becomes a surprising tool call.

Claim coverage / complete 26 / 26

All 26 included projects and all 13 core coding agents have fresh source receipts for this edition.

Builder or operator supervising multi-root, remote, or delegated coding work 20–30 minutes

Trace one permission handoff

In a disposable workspace with no production credentials, choose one tool action that could cross a project boundary. Record the selected environment, its workspace roots, its approval and filesystem rules, and whether a child or resumed task inherits that same context. Change only a non-sensitive test policy for a future turn, then verify whether an already-active task keeps its captured configuration. Add a regression test for a secondary root or delegated handoff; do not treat a successful test as proof that the allowed action itself is safe.

Two fresh merged Codex changes, their implementation paths, and focused tests agree on the narrow environment-bound permission model and on the distinction between active and future turn configuration.

Limit

These are public source and test receipts from Codex main. They do not establish release availability, a particular local or remote deployment’s configuration, independent security testing, or safety of every action that policy allows.

What would change this

Revise this call if public regression evidence shows a selected environment’s tool or child-agent path can silently use another environment’s profile, if project-root rules are not applied to a declared secondary root, or if a documented setting intentionally rewrites active-turn authority mid-flight.

Watch next. Watch for public tests that change roots or permission settings while remote execution or delegated work is in flight; those cases will show whether the environment boundary stays coherent under handoff and recovery.

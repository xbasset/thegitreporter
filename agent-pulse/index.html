Test whether sandbox policy survives a settings save

Qwen Code's new Linux tool boundary depends on operator policy being present at startup. A public follow-up records a settings replacement gap that can make the policy temporarily absent.

One decision-worthy insight. Action, effort, and rollback. 29 / 29 included projects monitored. Methodology ›

Today's Action

Audit / Project-specific claim
action

Test whether sandbox policy survives a settings save

What changed. The settings writer moves the existing settings file to a backup before installing its replacement. The policy reader treats a missing file as an empty scope. This is distinct from malformed or torn settings reads, which the merged change now rejects.

Why it matters. A command confinement test can pass while a concurrent settings save leaves a different session without the intended policy. Operators need to test admission as well as enforcement.

Claim coverage / complete 29 / 29

All 29 included projects and all 13 core coding agents have fresh source receipts for this edition.

Teams evaluating Qwen Code's Linux tool sandbox 30–60 minutes with an existing Linux test setup

Add a policy-continuity acceptance case

In a disposable Linux test environment containing PR #12267, establish the configured boundary with qwen sandbox --verify, then test settings saves concurrent with new session startup using harmless temporary-file probes. Require either the intended policy or an explicit refusal. Do not run this experiment against personal settings or sensitive files.

Confidence / developing

The settings writer and reader agree with the public follow-up mechanism; the timing-dependent reproduction is attributed to the upstream reviewer.

Limit

We did not independently reproduce the race, map installed releases or measure deployment incidence. Successful upstream isolation probes remain counterevidence to a general claim that the tool sandbox fails.

What would change this

Revise the call when the shipped writer keeps policy continuously visible and a concurrent reader-and-writer regression rules out an unconfined startup, or if another enforced scope demonstrably prevents the reported gap in the evaluated configuration.

Watch next. Closure of issue #12417's atomic settings-write work with platform-specific evidence and a regression that exercises real concurrent startup.

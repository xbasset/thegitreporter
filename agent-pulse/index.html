Test whether task-scoped learning stays out of global memory

Hermes's public source change tells the agent to put task-learned procedures, pitfalls, and task-specific user corrections in the relevant skill, reserving persistent memory for every-session facts. Today's Action

Test / Project-specific claim
action

Test whether task-scoped learning stays out of global memory

What changed. The fresh commit changes both the prompt builder and memory-tool schema so skills-first routing precedes the global-memory exception. Its regression test checks that this priority is present in the generated guidance, while the new schema names task-specific preferences and corrections as skill material because memory is injected into every future turn.

Why it matters. A correction about one task has a narrow future audience. If an agent stores it as general memory, unrelated sessions inherit a rule they did not earn; if it has a task home, it can remain detailed and useful without becoming background instruction everywhere.

What would change this

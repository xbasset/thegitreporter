Audit terminal-input policy separately from terminal visibility

If you evaluate an OpenClaw main-branch build containing its shared-terminal input change, audit the terminal-input path as a distinct authority: seeing or managing an operator-opened session should not by itself let an agent send a command into it.

Today's Action

Audit / Project-specific claim
action

Audit terminal-input policy separately from terminal visibility

What changed. The fresh public OpenClaw change removes agent-side terminal creation, derives input authority from the exact session execution policy, blocks deny mode, requires a one-shot approval for each non-full input, and checks the live delegated run and terminal again immediately before the PTY write.

Why it matters. A terminal is an execution boundary, while a shared terminal view is a collaboration feature. Keeping those decisions separate makes an operator’s trust choice inspectable, but the receipts are public implementation and tests rather than proof of any particular release or deployment configuration.

Claim coverage / complete 28 / 28

All 28 included projects and all 13 core coding agents have fresh source receipts for this edition.

Operator or security owner evaluating an OpenClaw build with shared terminal access 20–30 minutes in a disposable environment

Trace one harmless input from policy to terminal

In a disposable session and terminal, confirm which policy applies to agent input. Verify that deny blocks it, guarded or workspace access presents a separate one-shot review for each harmless command, and the request cannot complete after the agent run or terminal session has ended.

Confidence / developing

The merged public commit, its terminal-tool implementation, its changed protocol language, and focused behavior tests agree on the intended input boundary. The action remains an audit because the evidence does not establish release availability, defaults, or deployment-wide behavior.

Limit

These main-branch receipts do not establish that a release contains the change, that it is enabled by default, or that every gateway, terminal client, extension, and policy migration shares the same behavior.

What would change this

Revise or withdraw this call if public release guidance or regression evidence shows that an agent can create a shell, send guarded input without a fresh exact approval, retain authority after its run ends, or write through a replaced terminal manager.

Watch next. Watch for public release notes and configuration guidance that state how session permission modes, review delivery, and shared terminal ownership behave in supported upgrades.
